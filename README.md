# Ветви

Для общего HTTP-входа на этом VDC: [адрес `/vetvi/`, API, Nginx и применение](docs/public-http.md). Это явно выбранный владельцем режим HTTP на порту 80; схема через SSH ниже сохраняется для отдельного закрытого запуска.

Личное пространство задач: интерактивный граф, список и карточка над одной SQLite-базой. Интерфейс на русском. Нет биллинга, тарифов, подписок, пробных периодов или платных функций. Данные демонстрационного проекта синтетические и не подтверждают реальные рабочие статусы.

## Быстрый запуск на Windows

Требуется Node.js **24.12+** и npm. Node SQLite пока выводит предупреждение `ExperimentalWarning`; отдельный сервер базы данных не нужен.

```powershell
npm ci
Copy-Item .env.example .env
# Заполните OWNER_PASSWORD случайным паролем длиной минимум 12 символов.
npm run dev
```

Откройте [приложение](http://127.0.0.1:5173), введите логин `OWNER_LOGIN` (по умолчанию `admin`) и пароль `OWNER_PASSWORD` из локального `.env`. Пароль не публикуется и не возвращается API. Никогда не коммитьте `.env`.

`SEED_DEMO=true` при первом запуске добавляет категорию «Работа», проект «Регламент взаимодействия с VDC» и две параллельные ветки. Повторный запуск не дублирует проект. `false` запускает чистое пространство; первый проект можно создать в боковом меню.

Для обычного запуска собранного интерфейса:

```powershell
npm run build
npm start
```

Приложение и API доступны на [локальном сервере](http://127.0.0.1:3001). Сессия действует 12 часов; перезапуск сервера требует повторного входа, задачи сохраняются. Храните базу на надёжном локальном диске, а не на одновременно синхронизируемом несколькими устройствами SQLite-файле. Для размещения укажите `DATABASE_PATH` на постоянном томе вне OneDrive.

## Работа

- Граф: масштабирование, перемещение полотна, перетаскивание узлов, сворачивание веток, добавление подзадачи кнопкой `+`, сохранённая автораскладка. Вложенные ветки первоначально свёрнуты для читаемости. Положение узла хранится отдельно от структуры.
- Карточка: название, описание, статус, приоритет, срок, критерии, подтверждения, перенос всей ветки, связи и история. Изменения сохраняются явно; локальные правки можно отменить.
- «Связи»: зависимости задают порядок выполнения; обычные связи связывают темы. Родитель задаётся отдельно. Циклы дерева и зависимостей запрещены.
- Поиск и фильтры: статус, категория, срок, просроченные задачи, скрытие завершённых веток. Граф и список показывают одинаковые данные проекта.
- Завершение требует описания полученного результата. Критерии и ссылки на подтверждение необязательны. Сервер проверяет открытые подзадачи и зависимости. Документ сам по себе не доказывает согласование. При сомнении используйте «На проверке».
- Прогресс считает только конечные задачи; исключает архивные, удалённые и отменённые ветки. 100% не закрывает родителя. Показатель «Задачи проекта» в верхней панели — доля всех записей проекта со статусом «Выполнено», отдельно от прогресса веток.
- «Архив» отделён от выполнения. «Корзина» хранит удалённые задачи и историю; удалению поддерева предшествуют просмотр полного списка и явное подтверждение. Восстановление возвращает удалённый набор.
- Срок без времени — литерал `YYYY-MM-DD`. Точное время хранится в UTC и показывается в `Asia/Almaty`.

## Данные и резервные копии

Миграции выполняются при запуске, исходный SQL находится в `migrations/`. Общий `server/service.ts` обслуживает UI API и MCP; отдельного хранилища ChatGPT нет.

```powershell
npm run backup
# Или задайте новый файл явно:
npm run backup -- ./backups/manual.sqlite
```

Копия создаётся штатным SQLite backup API, включая данные WAL, проверяется `integrity_check` и не перезаписывает существующий файл. Для восстановления остановите приложение, сохраните прежнюю базу вместе с её WAL/SHM, затем укажите `DATABASE_PATH` на проверенную копию и запустите. Не заменяйте работающую базу.

Кнопки экспорта/импорта сохраняют JSON `formatVersion: 1` с задачами, связями, координатами и историей. Импорт транзакционный и **добавляет** данные: совпадающие ID отклоняются, существующие данные не перезаписываются. Для полного восстановления используйте чистую базу. Импортированная история помечается источником импорта; она не выдаётся за проверенные действия другого пользователя. Пароли и сессии не экспортируются. JSON и резервные копии содержат личные данные; защищайте их как исходную базу.

## MCP и локальное подключение ChatGPT

Для вашего локального режима используйте [инструкцию Secure MCP Tunnel](docs/local-chatgpt.md). Домен и внешний OAuth не нужны. Логин/пароль защищает UI; stdio MCP доступен доверенному локальному процессу и вашему туннелю.

Настройте собственный Secure MCP Tunnel по инструкции и выберите созданный личный плагин в ChatGPT. После перезагрузки компьютера запустите `npm run tunnel:start`; состояние — `npm run tunnel:status`, остановка — `npm run tunnel:stop`.

### Необязательный HTTP-вариант

Настоящий MCP endpoint `/mcp` использует официальный `@modelcontextprotocol/sdk`, Streamable HTTP, JSON Schema и OAuth metadata. UI и MCP проверяют одного владельца и права на каждую операцию. Каждая мутация требует `requestId`, изменения существующей задачи — `expectedVersion`. Повтор точного запроса с тем же ключом возвращает сохранённый результат; устаревшая версия даёт конфликт.

Читайте [инструменты и подключение ChatGPT](docs/mcp.md), [модель данных](docs/data-model.md), [проверенные требования безопасности](docs/security-requirements.md) и [исследование REA](docs/reference-analysis.md).

Для публичного удалённого подключения требуются HTTPS reverse proxy, постоянный диск и внешний OAuth-сервер с совместимой регистрацией клиента, PKCE S256 и выдачей JWT для audience вашего `/mcp`. Приложение является resource server, а не самодельным OAuth-провайдером. Заполните `PUBLIC_BASE_URL`, `OWNER_SUBJECT`, `OAUTH_ISSUER`, `OAUTH_AUDIENCE`, `OAUTH_JWKS_URL`; задайте `UI_ORIGIN` равным внешнему origin. Прокси должен передавать исходный Host. Публичный OAuth MCP требует HTTPS; исключение — loopback для разработки. Отдельный HTTP-режим UI не отменяет это требование.

Не открывайте локальный порт в интернет без этой настройки. Публикация и создание облачных ресурсов не выполнялись. Настоящее подключение ChatGPT считается проверенным только после успешного вызова инструмента из ChatGPT. MCP не запускает фонового ассистента.

`OWNER_SUBJECT` — также идентификатор владельца записей. Его смена не передаёт существующие данные другому субъекту. Определите его до начала реальной работы. При переносе уже созданных записей сначала экспортируйте JSON и сделайте backup, затем настройте новый subject с новым пустым `DATABASE_PATH`, отключите демоданные и импортируйте JSON. Прежнюю базу сохраните для отката.

## Проверки

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm audit
```

Тесты используют временные базы и локальный тестовый OAuth issuer. Они проверяют реальные HTTP MCP-вызовы официальным клиентом, общий UI API, перезапуск, историю, изоляцию владельцев, read-only scope, конфликты, идемпотентность, циклы, перенос, завершение по результату, корзину, импорт и онлайн-бэкап. Личные отчёты сквозных проверок, ссылки на чаты и данные рабочего экземпляра в репозиторий не входят.

## Устройство проекта

`src/` — React и React Flow. `server/service.ts` — транзакционные правила. `server/schema.ts` и `migrations/` — база. `server/index.ts` — HTTP API, `server/mcp.ts` — общие MCP-инструменты, `server/stdio.ts` — локальный MCP. `server/auth.ts` — сессии, OAuth и проверка доступа. `server/backup.ts` — проверяемое резервное копирование. `tasks/github-publication.md` — подготовка публичного репозитория. Локальная спецификация `tasks/todo.md` исключена из Git, поскольку содержит сведения рабочего экземпляра.
