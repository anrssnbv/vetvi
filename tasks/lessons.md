# Уроки

- Перед `runuser` выбирать рабочий каталог, доступный целевому пользователю. Унаследованный закрытый cwd даёт `spawn esbuild EACCES` даже при исправном бинарнике; не менять права бинарника без проверки.
- Перед изменением общего gateway сверять фактический образ и Compose: если платформа уже активирована, добавлять только её socket mount, сохраняя действующие API, сети и данные. Журналировать этап и строку остановки установщика.

- Развёртывать из фиксированного снимка проверенных файлов; не связывать установщик с изменяющимся рабочим деревом соседнего проекта. Проверять также состав Docker build context и `.dockerignore`.

- При выборе публичного HTTP учитывать явное решение владельца: ограничивать исключение веб-входом, сохранять Host/Origin/CSRF и не переносить его на OAuth/JWKS.

- Для локального приложения отдельно определять вход в UI и доступ ChatGPT к MCP. Проверять Secure MCP Tunnel прежде, чем объявлять публичный домен и внешний OAuth обязательными.
- Не повторять форму подтверждения, которая возвращает not_approved без завершённого пользовательского выбора. Получить точное текстовое подтверждение файла и переменной, если защищённая форма недоступна; не считать общую просьбу подтверждением места хранения секрета.
- Для tunnel-client в Windows использовать прямые слеши в путях команды MCP и проверять фактический process_running/healthy/ready, а не только факт запуска процесса.

- Для UI по обычному HTTP не использовать secure-context API `crypto.randomUUID`; генерировать requestId через доступный `crypto.getRandomValues` и проверять форму в настоящем insecure context.
- При изменении правил завершения синхронно менять UI, общий TaskService, импорт и описание MCP; сохранять старую историю/ссылки и проверки зависимостей.

- При ограниченном sudo развёртывать код как служебный пользователь vetvi; от root вызывать только явно разрешённые команды служб. Рабочий каталог выбирать внутри /opt/vetvi, приватные файлы workspace передавать по stdin. Не требовать общего NOPASSWD для root или запуска изменяемого скрипта от root.

- В фильтре «Просроченные» проверять просроченную подзадачу под непросроченным свёрнутым родителем: результаты должны быть самостоятельным списком и не наследовать сворачивание ветки. Счётчики и список проектов строить из одного набора; глобальную просрочку считать только по активным данным.

- Просмотр «Список» для специальных разделов не должен менять стандартное открытие проекта: боковой список и мобильный выбор открывают граф, возврат ко всем проектам тоже. В «Просроченных» сохранять отдельный список подзадач.

- «Личные задачи» в sidebar — раскрываемая группа списка проектов: стрелка и название сворачивают её вместе. Уточнять видимый заголовок перед добавлением нового дерева задач; клик по отдельному проекту сохраняет открытие графа.
- В боковом списке новых проектов показывать только задачи без parentId. Подзадачи сохранять в графе, карточке и просроченных; проверять обычный и личный новые проекты.
