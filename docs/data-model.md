# Модель и сохранность данных

Проекты также поддерживают мягкое удаление: `delete_project` требует актуальную версию и `confirmationTitle`, точно совпадающее с названием проекта. Активные незавершённые задачи блокируют удаление; выполненные, отменённые, архивные ветви и задачи из корзины не блокируют. Проект и все оставшиеся задачи перемещаются в корзину одной транзакцией без смены статуса задач; уже удалённые записи не переписываются. Пользователь подтверждает, что дальнейшая работа не требуется. Проект и его история остаются в базе. `list_projects` скрывает удалённые проекты, `includeDeleted: true` включает их для интерфейса корзины. `restore_project` возвращает метаданные проекта; `restore_task` автоматически возвращает связанный проект при восстановлении задачи. Создание и перенос задач в удалённый проект запрещены. JSON-экспорт сохраняет состояние удаления проекта, импорт проверяет его согласованность с задачами.

SQLite — единственное постоянное хранилище. `server/schema.ts` применяет миграцию 1 и регистрирует её в таблице `migrations`; SQL структуры приведён в `migrations/001-initial.sql`. UI и MCP вызывают `TaskService.execute`. Каждая операция проверяет владельца, права и доступ ко всем затронутым записям.

Задачи имеют стабильный ID, родителя, проект, порядок, описание, статус, приоритет, срок, критерии, подтверждения, результат, причину ожидания, версии и временные отметки. Родительская связь находится в записи задачи; зависимости и обычные связи — в таблице `links`; визуальные координаты — в `positions`. Обычная связь симметрична: видна и удаляется с любой стороны, повторное добавление с другой стороны не создаёт дубликат. Изменение такой связи повышает версии обеих задач и записывается в историю обеих задач в одной транзакции. Перенос сохраняет потомков и историю. Циклы дерева и зависимостей запрещены.

Любое изменение требует `requestId`. Точный повтор возвращает прежний сохранённый результат; другой запрос с тем же ключом получает конфликт. Изменение существующей задачи требует `expectedVersion`. Запись задачи, история и результат для повторного запроса сохраняются в одной транзакции `BEGIN IMMEDIATE`. Проверки версий предотвращают потерю изменений между UI и MCP.

## Прогресс и завершение

Прогресс равен доле выполненных конечных задач. Отменённые, архивные и удалённые ветки исключаются целиком вместе с потомками. Если у родителя есть только исключённые ветки, число учитываемых листьев равно нулю; родитель не подставляется вместо них. Если задача структурно не имеет детей и активна, она сама является листом. Прогресс 100% не завершает родителя.

`complete_task` требует конкретного непустого описания результата. Критерии и ссылки на подтверждение необязательны; существующие ссылки сохраняются. Все неудалённые потомки должны быть выполнены или отменены, включая потомков отменённых задач. Все непосредственные зависимости должны быть выполнены и не удалены. Обычный `update_task` не завершает задачу, не открывает закрытую задачу и не меняет критерии выполненной задачи. Для этого сначала нужен `reopen_task` с причиной. Повторное открытие переводит выполненных родителей и зависимые задачи в состояние «на проверке» и сохраняет историю.

Для необязательных ссылок проверяется корректный формат. Сервер не удостоверяет содержание внешнего документа и не заменяет человеческого подтверждения согласования.

## Архив, удаление и восстановление

Архивирование не меняет статус выполнения. `search_tasks` по умолчанию или с `archived:false` исключает архивные задачи и их потомков. `archived:true` выбирает только архивные ветки. Архивируется выбранная запись; потомки скрываются через родителя и не теряют собственные отметки архива. Для возврата ветки восстанавливается архивный родитель; отдельно архивированные потомки остаются архивными.

Удаление всегда обратимо. `preview_delete` возвращает затронутые записи и ID. `delete_task` требует явного `subtree:true`, актуального списка `previewIds` и версии корня. Удалённые записи получают общую группу восстановления. `restore_task` восстанавливает группу; ранее удалённые отдельно записи не восстанавливаются вместе с ней. `deleted:true` выбирает только удалённые записи независимо от фильтра архива.

## Сроки и история

`dueDate` хранит дату `YYYY-MM-DD` без преобразования часового пояса. `dueAt` принимает корректную дату и время с часовым поясом, сохраняется в UTC. Сроки отображаются в `Asia/Almaty`. Системные временные отметки записываются в UTC.

История содержит автора, время, действие, старую и новую записи, причину и подтверждение завершения. Изменения связей и координат дополнительно содержат старое и новое значение операции. `get_task` возвращает последние 100 событий задачи; `get_changes` предоставляет постраничный журнал после числового курсора. `search_tasks` возвращает записи с прогрессом и связями; историю запрашивают отдельно.

## JSON и резервные копии

Экспорт `formatVersion:1` включает категории, проекты, задачи, связи, координаты и всю историю. Импорт добавляет данные транзакционно; существующие ID никогда не перезаписываются. Для восстановления полного экспорта используйте пустую базу. Импорт проверяет структуру, версии, даты, подтверждения, родителей, циклы и правила завершения. Владельцем импортированных записей становится автор импорта. Импортированная история помечается `actor:import:<владелец>`, `originalActor` и `importedBy`; исходный автор является историческими данными, а не доказанной личностью.

`npm run backup -- ./backups/manual.sqlite` создаёт отдельный согласованный снимок через SQLite online backup API, включая данные открытого WAL. Команда проверяет `PRAGMA integrity_check` и чтение таблицы записей, отказывается перезаписывать существующий файл. Источник задаётся `DATABASE_PATH`. Для восстановления остановите приложение и укажите `DATABASE_PATH` на проверенную копию. JSON-экспорт содержит данные владельца; SQLite-копия содержит всю базу и должна храниться с соответствующим доступом.

## Проверки

`node --import tsx --test server/service.test.ts` проверяет циклы, перенос, версии, повторы, изоляцию владельцев, запреты завершения, прогресс, архивные ветки, восстановление, реальное закрытие и повторное открытие SQLite, JSON-перенос, враждебный импорт и независимое чтение online backup. Проверка внешнего содержания подтверждений и развёртывание в эти тесты не входят.
