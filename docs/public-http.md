# Общий HTTP-вход с multiagent platform

Текущий адрес Space: `http://92.46.191.252/space/`. Владелец выбрал HTTP на порту 80. Пароль и cookie передаются без шифрования. Обмен задачами между приложениями отложен; логины и базы остаются независимыми.

## Действующий gateway

30.10.2026 на сервере активирована платформа spec 18: `sk-ai-http-login:spec18`, API, PostgreSQL и Qdrant. Её Nginx уже содержит маршруты `/platform/`, `/platform/api/v1/` и `/vetvi/`. Установщик Ветвей добавляет только read-only mount `/run/vetvi-proxy` в операторский `/home/admin-srv/.config/sk-ai-platform/compose.yaml` и пересоздаёт только `nginx` с `--no-deps --no-build --pull never`. API, базы, пользователи, сети и образ платформы сохраняются. Включён операторский lock; после применения проверяются прежний image ID gateway и неизменность ID остальных backend-контейнеров.

Рабочий socket принадлежит `vetvi`, группе 1000, имеет права 0660. Каталог смонтирован в Nginx read-only; штатный `systemd-socket-proxyd` передаёт запросы на `127.0.0.1:3001`. Порты Node 3001 и tunnel admin 3002 остаются loopback-only.

Исторический снимок статического профиля из commit f757332 сохранён в `.local-tools/vdc/nginx-release`. Действующий установщик использует уже активированную платформу; этот прежний статический профиль не является конфигурацией текущего запуска.

## UI, API и MCP

Под `/space/api/` доступны штатные session/login/logout и tools API. Вход требует прежний пароль владельца. Проверки Host, Origin, CSRF, владельца, версии и requestId сохраняются. Cookie имеет Path `/space` и не отправляется на `/platform`. Приложения с одним origin всё равно разделяют браузерную границу доверия.

Production build выполняется с префиксом:

```bash
npm run build -- --base=/space/
```

В `/etc/vetvi/app.env` меняются только:

```dotenv
PUBLIC_BASE_URL=http://92.46.191.252/space/
UI_ORIGIN=http://92.46.191.252
ALLOW_INSECURE_HTTP=true
```

Пароль, `OWNER_SUBJECT`, база и seed сохраняются. Публичный HTTP выключен по умолчанию; это явное исключение веб-интерфейса. Публичный OAuth MCP по HTTP запрещён. MCP продолжает работать через прежний приватный stdio-туннель; его административный интерфейс наружу не публикуется.

## Применение и диагностика

```bash
sudo bash /home/admin-srv/vetvi/ops/vdc/apply-http.sh
```

Установщик проверяет действующий образ/конфигурацию gateway, хэши старого кода и подготовленного архива. Сохраняет код/env/операторский Compose/image ID и согласованную копию SQLite. Все команды `runuser -u vetvi` выполняются из `/opt/vetvi`, доступного сервисному пользователю: закрытый домашний cwd приводит к `spawn esbuild EACCES` даже с исправным бинарником.

При ошибке после начала обновления восстанавливаются прежние код/env Ветвей и конфигурация gateway. Текущая SQLite и базы платформы не откатываются. Ручной откат требует полного каталога последнего применения:

```bash
sudo bash /home/admin-srv/vetvi/ops/vdc/rollback-http.sh /var/lib/vetvi/deployments/http-TIMESTAMP
```

Приватный журнал создаётся в `.local-tools/vdc/apply-http.log`, владелец admin-srv, права 600. Ошибка содержит этап и строку. Пароли и содержимое конфигураций в журнал не выводятся.

Проверка непосредственно на сервере после применения:

```bash
curl -fsS -H 'Host: 92.46.191.252' http://127.0.0.1:3001/health
curl -fsS http://92.46.191.252/space/health
curl -fsS http://127.0.0.1:3002/readyz
```

Включаются также ранее разрешённые ежедневные локальные копии с хранением последних 14. Старый SSH-origin `127.0.0.1:13001` после изменения PUBLIC_BASE_URL перестаёт быть адресом UI.

## Проверено и не проверено

Прошли regression checks cwd/tsx, сохранения всей конфигурации при добавлении mount, прав/владельца, повторного запуска и отказа конфликтующему mount, а также вывода этапа preflight failure. Копия реального Compose после изменения отличается только `nginx.volumes`; нормализованный Docker Compose подтверждает это.

Тот же реальный образ gateway проверен на отдельном loopback-порту с существующим API платформы и отдельной синтетической базой Ветвей. HTTP acceptance прошёл: assets/MIME/CSP, вход/сессия/выход Ветвей, Host/Origin/CSRF, cookie Path, маршруты платформы и её отдельная авторизация. Виртуальные публичные Host/Origin сохранены при изолированном TCP transport. Реальные задачи не менялись; платформе отправлялись только анонимные GET.

Новый установщик от root и его live rollback ещё не выполнены. Публикация реальных Ветвей, независимый сторонний ПК и перезагрузка остаются отдельными проверками.

## Переход на Space — 05.11.2026

Основной UI/API перенесён на `/space/`. `/vetvi` и `/vetvi/*` возвращают 308 на новый адрес с сохранением пути и параметров запроса; метод POST сохраняется. Внутренние API запрещены снаружи под обоими префиксами. После смены пути нужно войти заново: cookie и защищённые сессии привязаны к пути. Данные, пути служб, закрытый протокол платформы и параметры связи с чатом не переименовываются.

Для этого перехода сохраняются точные исходники/dist, env и эффективная конфигурация gateway. Меняются только PUBLIC_BASE_URL, сборка и правила публичного маршрута; `/chat/`, `/onedrive/`, `/platform/` сохраняются. Откат возвращает эти файлы и перезагружает службы, без отката текущей базы данных. Инструкции первоначальной установки выше описывают старый выпуск, а не повторный запуск миграции.
