# MCP и требования безопасности

Проверено 30 октября 2026 года по первичным источникам. Это требования и границы проверки; фактические результаты тестов фиксируются отдельно.

## Транспорт

[Спецификация MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports): endpoint принимает JSON-RPC через POST; GET может возвращать 405, если поток событий не предоставляется. При наличии недопустимого Origin требуется 403. Локальный сервер привязывается к loopback. Для реализации используется [официальный TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk), а не REST под названием MCP.

## Авторизация

[OpenAI Authentication](https://developers.openai.com/plugins/build/auth): для защищённых данных применяется OAuth 2.1 authorization-code с PKCE S256. Сервер публикует Protected Resource Metadata и сообщает его адрес через `WWW-Authenticate` при 401. В метаданных указан канонический resource и внешний authorization server. Каждая операция проверяет подпись, issuer, audience, срок токена и scopes; затем права владельца на запись. Инструменты объявляют OAuth scopes через `securitySchemes` и соответствующие метаданные.

Провайдер авторизации должен поддерживать discovery и совместимую регистрацию/идентификацию клиента: CIMD, DCR либо заранее настроенный OAuth-клиент. Callback берётся из страницы управления подключением. Поддержка issuer identification определяет используемый callback; его нельзя угадывать. Произвольный статический API-ключ и client-credentials grant не заменяют пользовательский OAuth для ChatGPT.

[Спецификация MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) разделяет ресурсный сервер и сервер выдачи токенов. Приложение реализует ресурсный сервер; параметры реального OAuth-провайдера задаются при размещении. Передача токенов, выданных для другого audience, запрещена.

## Подключение и доказательство интеграции

[OpenAI Connect and test](https://developers.openai.com/plugins/deploy/connect-chatgpt): ChatGPT должен достигать публичного HTTPS endpoint либо приватного сервера через Secure MCP Tunnel. Для публичного HTTP-варианта используется адрес с `/mcp`. Локальная проверка официальным MCP-клиентом доказывает работу протокола, но не подтверждает подключение ChatGPT.

Размещение и платные ресурсы не создаются без отдельного указания. Для удалённой проверки нужны выбранный адрес/хостинг, OAuth-провайдер, разрешённый субъект владельца, настройка callback и успешный вызов инструмента из ChatGPT. До этого удалённая интеграция считается непроверенной.

## Прикладные правила

UI и MCP используют один TaskService и одну SQLite-базу. Поля задач и внешнее содержимое являются данными и не меняют полномочия. Изменения требуют ожидаемой версии и requestId; повтор не должен создавать второе изменение. Завершение проходит отдельную серверную проверку непустого результата, подзадач и зависимостей. Критерии и ссылки на подтверждения необязательны. Обычное редактирование не обходит эту проверку. Журнал сохраняет автора, время, прежнее/новое значение и обоснование.

Секреты исключены из Git и логов. UI использует защищённую cookie-сессию; удалённый MCP использует OAuth access token. Синтетические данные не удостоверяют реальные рабочие статусы. Наличие MCP не означает постоянную фоновую работу ChatGPT.
